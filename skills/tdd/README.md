# tdd

Test-driven development as a red-to-green loop: what a good test is, where tests go (seams agreed with the user), the anti-patterns, and the rules of the loop. `tests.md` and `mocking.md` give examples. Run it with `/tdd`, or it loads when you ask for test-first work. `start-implementation` points to it for behaviour changes that have a test seam.
