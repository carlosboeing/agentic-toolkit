# start-requirements

Establish intended behavior and success criteria. For a new product or capability, clarify consequential gaps and persist a brief before technical design. Reuse an existing sufficient requirements owner. Routine clear changes may keep requirements in the request, issue or session; an explicit lighter route wins.

Run `/start-requirements [brief or source-path] [help]` or request its work in natural language. Use `/start-requirements help` for the synopsis.

The complete procedure is in [SKILL.md](SKILL.md). Project instructions own storage, review, and delivery permissions. The [requirements quality contract](references/requirements-contract.md) gives required answers, suggested headings, and compact and substantial examples. Separate sessions and agents are optional; no fixed questionnaire or extra approval ceremony is added. The skill stops at its requested boundary unless an explicit workflow already authorizes continuation.

## Dependencies and installation

No additional runtime or service is required. Use the available project and harness capabilities; unavailable capabilities are reported rather than simulated. Git, Bash, and `rsync` are needed for the toolkit installation procedure. Install the complete directory using the [shared instructions](../README.md#install-one-skill). No global installation is performed by invoking this phase.
